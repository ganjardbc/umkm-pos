## Test Types

What exists today (facts from the code):

| Workspace | Tooling | Command | Notes |
|---|---|---|---|
| `apps/api` | Jest 30 + ts-jest, `@nestjs/testing` | `pnpm --filter umkm-pos-api run test` | 24 `*.spec.ts` files in `src/`; run by CI |
| `apps/api` (e2e) | Jest + supertest | `pnpm --filter umkm-pos-api run test:e2e` | Only `apps/api/test/app.e2e-spec.ts`; not run by CI |
| `apps/merchant` | — | none | 7 `*.test.ts` files in `modules/dashboard/` with no test runner in `package.json` → cannot be run |
| `apps/admin`, `apps/landing`, `packages/*` | — | none | No tests |

For the Vue apps the only gate is `build` (`vue-tsc -b && vite build`).

Proposed rules (Claude's recommendation, 2026-10-03 — **not decided by the team**):
- A change to a service or guard in `apps/api` → a `*.spec.ts` unit test next to the file is required.
- A change to transaction commit, stock, shifts, or tenant scoping → a test proving that rule is required.
- A frontend change → `build` must pass; UI tests cannot be required until a test runner exists.

## Conventions

From the `apps/api` code:
- Test files sit next to the file under test: `stock.service.ts` → `stock.service.spec.ts`. E2E tests are in
  `apps/api/test/` with the `.e2e-spec.ts` suffix.
- `@prisma/client` is mocked globally in `apps/api/jest.setup.ts`; each spec supplies a `mockPrisma` made of
  `jest.fn()` via `{ provide: PrismaService, useValue: mockPrisma }` (example:
  `apps/api/src/stock/stock.service.spec.ts`). No test uses a real database.
- Modules are tested through `Test.createTestingModule(...)`.
- One `describe('<ClassName>')` per class.
