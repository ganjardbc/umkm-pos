## Data Flow

1. Login: `POST /api/v1/auth/login` → JWT + user/merchant/outlet/permission payload, stored in
   `localStorage` by the frontend.
2. Every request: the axios interceptor adds `Authorization: Bearer <token>` and, when an outlet is active,
   `X-Outlet-Id`.
3. In the API: global `JwtAuthGuard` (`app.module.ts`) → `PermissionGuard` + `@RequirePermission()` →
   controller → service → `PrismaService` → MySQL. `merchant_id` always comes from the JWT.
4. Responses are wrapped by `TransformInterceptor`; errors are formatted by `HttpExceptionFilter` (see
   `docs/api-contract.md`).
5. Customer self-order has no login: routes marked `@Public()` in `customer-catalog.controller.ts`, with the
   session sent in the `X-Customer-Session-Token` header.
6. A POS transaction commit decrements stock and writes the logs in one database transaction (see
   `docs/architecture/design.md`).

## External Dependencies

| Service | Used for | Evidence |
|---|---|---|
| MySQL | Primary database | `apps/api/prisma/schema.prisma` (`provider = "mysql"`), service `umkm-pos-db` in `docker-compose.yml` |
| S3 / S3-compatible endpoint | File uploads | `@aws-sdk/client-s3` in `apps/api/package.json`; env `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `S3_BUCKET_NAME`, `S3_ENDPOINT` |
| Local disk | Uploads (default: `STORAGE_DRIVER` = `local`; `s3` selects S3) | `apps/api/src/uploads/uploads.service.ts`; `main.ts` serves `uploads/` at `/uploads/local` |
| GitHub Actions + VPS (SSH, Docker Compose) | CI and deploy | `.github/workflows/ci.yml` |
| Linear | Ticket tracker (via MCP) | `.mcp.json`, `.caf/tasks/README.md` |

There is no payment gateway or third-party auth provider in the code — authentication is the API's own JWT.
