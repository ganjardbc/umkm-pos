## Why the Files in This Folder Are Good Examples

> File picks and Do/Don't below were proposed by Claude from the code (2026-10-03) — not yet confirmed by the team.

Two earlier paths (`apps/merchant/src/components/UiSearch.vue`, `apps/merchant/src/composables/useFileUpload.ts`)
moved to `packages/ui` — their examples now live in the `packages/ui` RULES.md. The replacements come from
`docs/golden-examples/README.md`. These files show one feature module end to end:
`services/api.ts` → store/page → permission gating.

## Do

- All HTTP calls live in `modules/<name>/services/api.ts` as named exports; import the client from
  `@/plugins/axios`.
- Endpoint paths are written in full with the `/api/v1/` prefix.
- Permission codes come from the module's `services/rbac.ts` (`READ`, `CREATE`, `UPDATE`, `DELETE`) and are
  checked with `isHasPermission()` from `@/helpers/auth`.
- Route names/paths come from `services/constants.ts` (`PREFIX_ROUTE_NAME`, `PREFIX_ROUTE_PATH`).
- Stores are split into `state.ts` / `getters.ts` / `actions.ts` / `index.ts`.
- State used by a single page: call the service straight from the page, no store.

## Don't

- Don't call axios directly from a component, store, or composable.
- Don't hardcode permission strings or route names.
- `reports/services/api.ts`: `getListreports`, `getDetailreports`, `postreports`, `putreports` are Hygen
  scaffold leftovers — their path is `/api/reports` without `v1` and the names are not camelCase. Don't copy.
- `customer-catalog/stores/actions.ts` uses `(this as any)` to reach state. That is how it is today, not the
  goal — don't spread it to new stores.
- `any` parameters in services (`data: any`, `options: any`) appear in almost every `api.ts`; in new code use
  the types from `services/types.ts` where they exist.
