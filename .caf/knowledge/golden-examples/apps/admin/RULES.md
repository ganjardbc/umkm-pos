## Why the Files in This Folder Are Good Examples

> File picks and Do/Don't below were proposed by Claude from the code (2026-10-03) — not yet confirmed by the team.

Admin mirrors the merchant app's module layout but talks to `/api/v1/admin/*`. These files show the three
things that are specific to it: admin-scoped services next to shared ones, the menu registry, and the
split-file Pinia store.

## Do

- Admin endpoints use the `/api/v1/admin/...` prefix and go through `@/plugins/axios`.
- Anything generic (upload, signed URL) is imported from `@umkm-pos/ui`, not re-implemented.
- A new module registers its menu entry in `services/menus.ts` using its own `services/constants.ts` and
  `services/rbac.ts`.
- Stores keep the four-file split and are named `use<Module>Store`.

## Don't

- Don't treat `auth/stores/actions.ts` and `getters.ts` as examples of content — they are empty scaffolds.
  For a store with real actions see `apps/merchant/src/modules/customer-catalog/stores/actions.ts`.
- Don't copy `AssignOutletModal.vue` wholesale; split a component that large.
- Don't call merchant (non-`/admin`) endpoints from this app.
- `options: any = {}` in the service signatures is the existing habit, not a rule to spread.
