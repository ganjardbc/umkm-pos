## Why the Files in This Folder Are Good Examples

> File picks and Do/Don't below were proposed by Claude from the code (2026-10-03) — not yet confirmed by the team.

The first three files are the team's own picks in `docs/golden-examples/README.md` (controller, service,
query DTO); the last two were auto-picked by `caf-initiator`. Together they show the path of one request:
validated DTO → thin controller → tenant-scoped service.

## Do

- `merchant_id` and the user `id` always come from `@CurrentUser('merchant_id')` / `@CurrentUser('id')` and are
  passed to the service as arguments (`products.controller.ts`).
- Every protected endpoint has `@RequirePermission('<resource>.<action>')`; the controller uses
  `@UseGuards(PermissionGuard)`.
- Controllers only delegate: a single `return this.<service>.<method>(...)`.
- Every Prisma `where` on tenant data includes `merchant_id: merchantId` (`store-tables.service.ts`).
- Record not found → `NotFoundException`; duplicate → `ConflictException`.
- List + filter endpoints take one `@Query() query: XxxQueryDto` that `extends PaginationDto`.
- DTO fields are snake_case, matching the database columns.
- Prisma is reached through the `PrismaService` injected in the constructor.

## Don't

- Don't take `merchant_id` from the body, query string, or route params.
- Don't write Prisma queries or business `if` logic in a controller.
- Don't create `new PrismaClient()` in a service (there is none in `apps/api/src`).
- Don't mix `@Query('field')` and `@Query() dto` on the same endpoint.
- `csv-export.service.ts` uses `Record<string, any>` — acceptable for a generic export utility, not for
  domain types.
- Permission codes are inconsistent in the codebase (`merchants.*` is plural, the rest singular; both
  `product.view` and `product.read` exist). For a new resource use the singular `<resource>.<action>` form;
  don't copy the plural one.
