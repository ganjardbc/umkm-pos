## Why the Files in This Folder Are Good Examples

> File picks and Do/Don't below were proposed by Claude from the code (2026-10-03) — not yet confirmed by the team.

Everything here is consumed by both `apps/merchant` and `apps/admin`, and the package is source-only. The
files show the three rules that keep that working: no `@/…` imports, state in through props, HTTP through the
injected client.

## Do

- Component names start with `Ui` and stay presentational.
- Data and permissions arrive as props (e.g. `UiSidebarMenu` takes `menus` + `hasPermission`).
- HTTP calls use `getApiClient()` from `../http`, called lazily inside the function.
- Composables that hold global UI state keep the `ref` at module level.
- After a change, typecheck the package and build both consuming apps.

## Don't

- Never import `@/…` or an app's axios instance.
- Don't decide what a login response means here — the package only stores the session (`auth/`); each app's
  `src/helpers/auth.ts` owns `setAuth()`.
- Don't add a new source root without a Tailwind `@source` line, or its classes are dropped from the bundle.
- Default labels in `useGlobalConfirm.ts` are hardcoded Indonesian (`'Batal'`, `'Ok, Lanjutkan'`) — existing
  behaviour, not a pattern for new components that need translation.
- `options: any = {}` in `services/uploads.ts` is the existing habit, not a rule to spread.
