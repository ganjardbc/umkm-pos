## Review Notes — GAN-115
Ticket: GAN-115
Agent: caf-reviewer
Verdict: APPROVE

### Security Audit

None. This is a purely presentational frontend change — no API calls added, no new data
exposure, and no changes to RBAC permission guards. The existing
`:disabled="!isCanUpdate"` and `:disabled="!isCanDelete || !user.is_active"` bindings
carry over correctly. Merchant data (`user.merchants?.name`) was already fetched and
displayed in the old DataTable; its presence in the card is not a new exposure.

**Improvements over the spec:**

- Avatar `<img>` and fallback `<div>` both gain `shrink-0`, preventing layout collapse
  on narrow cards when the name is long — a good defensive addition.
- `user.merchants?.name` uses optional chaining (vs the old `slotProps.data.merchants.name`
  without optional chaining), which is strictly safer against missing relation data.
- `users` ref typed as `ref<any[]>([])` instead of the untyped `ref([])` that produced a
  TypeScript `never[]` inference error — a legitimate bug fix caught during implementation.
- `class="px-0!"` added to `<UiPagination>` for visual consistency with the transaction
  page; was absent in the original DataTable wrapper version.

**Minor observations (non-blocking):**

1. **`UiLoading` is auto-registered via `unplugin-vue-components`** (confirmed in
   `components.d.ts`). The explicit `import UiLoading from '@/components/UiLoading.vue'`
   added to `<script setup>` is therefore redundant — it won't cause a bug, but it diverges
   from the pattern used for `UiCard`, `UiSearch`, and `UiPagination`, which are NOT manually
   imported (they rely on the same auto-import mechanism). This is a style inconsistency the
   requirements spec itself asked for, so it is not a defect in the implementation — just
   worth noting for future cleanup. The QA report and verify-report correctly call this out as
   a task checkbox item; the spec was followed as written.

2. **Search is a stub** (`console.log(form.value)`). This was already the case before the
   change and is inherited from the original file. It is out of scope for this ticket.

3. **`components.d.ts` incidental change**: The diff shows a cosmetic reordering of comment
   lines (`// biome-ignore lint: disable` moved). This is auto-generated by
   `unplugin-vue-components` on build and is not authored manually — harmless.

4. **No `min-h` on `UiLoading`**: The `UiLoading` component uses `height: 100%` in its
   scoped style, which requires an ancestor with a defined height to center properly. When
   used as a top-level child of `space-y-4`, it collapses to zero height and the spinner
   is invisible. This is the same behavior seen in the transaction module (which uses the
   same pattern) and may be an existing known limitation — not introduced by this ticket.

### Verdict Rationale

The implementation is a clean, spec-faithful replacement of `<DataTable>` with a responsive
card grid. All 8 functional requirements and 3 non-functional requirements are satisfied. The
build passes (vue-tsc + vite, 834 modules, zero errors). QA independently verified every
acceptance criterion. The incidental improvements (optional chaining, `shrink-0`, TS type
fix) are conservative and correct. No security issues, no regressions, no unintended scope
creep. The single minor style note (redundant explicit import) is a carry-over from the
spec's own instruction and does not affect runtime behaviour.

### For Developer

- **Optional cleanup (not required):** The explicit `import UiLoading from
  '@/components/UiLoading.vue'` in `<script setup>` can be removed since `UiLoading` is
  already auto-registered by `unplugin-vue-components`. Aligns with the pattern used by
  `UiCard`, `UiSearch`, and `UiPagination` in this same file.
- **Future work:** The `search()` function is still a no-op stub. Consider wiring it to
  `fetchUser` with a debounce (separate ticket).
- **`UiLoading` height:** If the loading spinner appears invisible in practice, consider
  adding `min-h-[200px]` or similar to the loading state wrapper — same recommendation
  applies to all modules using this component.
