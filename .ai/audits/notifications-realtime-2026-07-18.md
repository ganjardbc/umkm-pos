## Backend — `apps/api/src/notifications/`

### 1. Fitur notifications pasif total — tidak ada producer yang membuat notifikasi
- **Lokasi**: `apps/api/src/notifications/notifications.service.ts` (seluruh file — hanya `findAll`, `findOne`, `markAsRead`, `markAllAsRead`, tidak ada `create`)
- **Kategori**: missing-feature
- **Severity**: HIGH
- **Deskripsi**: Grep codebase (`prisma.notifications.create`) hanya match di `notifications.service.ts` sendiri (tidak dipanggil) dan `apps/api/prisma/seed.ts`. Tidak ada domain service (transactions, inventory/stock, shifts) yang memanggil notification creation saat event bisnis terjadi. Endpoint read (`GET /notification`, dst) berfungsi, tapi data yang bisa dilihat user hanya hasil seed manual — fitur notifikasi secara efektif tidak pernah terisi data nyata di production.
- **Rekomendasi singkat**: Tambahkan `NotificationsService.create()` + wiring dari domain event yang relevan (order masuk, stok menipis, shift dibuka/ditutup, dst) sebelum membangun lapisan realtime di atasnya — realtime tanpa producer tidak ada gunanya.

### 2. Tidak ada transport realtime (WebSocket/SSE) di backend maupun frontend
- **Lokasi**: tidak ditemukan `Gateway`/`WsAdapter`/`socket.io` di `apps/api/src`; tidak ditemukan `EventSource`/socket client di `apps/web/src`
- **Kategori**: missing-feature
- **Severity**: MEDIUM
- **Deskripsi**: Notifikasi hanya diambil via `GET` manual saat komponen mount (`UiSidebarNotification.vue:80`, `pages/index.vue:66`). Tidak ada polling interval maupun push channel — badge unread tidak update tanpa reload/reopen popover.
- **Rekomendasi singkat**: Kalau mau realtime, servis terpisah (NestJS Gateway berbasis socket.io/ws) lebih cocok daripada nempel di `NotificationsModule` — perlu room per `user_id`+`outlet_id` yang divalidasi dari JWT (bukan client input), konsisten dengan aturan scoping project ini.

### 3. `ListNotificationsDto.limit` tidak punya batas atas

### 4. `findAll`/`findOne` melewati filter outlet kalau `outletId` kosong
- **Lokasi**: `apps/api/src/notifications/notifications.service.ts:22-26` dan `:53-56`
- **Kategori**: cross-tenant-scope (partial)
- **Severity**: MEDIUM
- **Deskripsi**: `where` clause pakai `...(outletId ? { outlet_id: outletId } : {})` — kalau `outletId` undefined (mis. user tanpa active outlet di request context), filter outlet hilang total dan query mengembalikan notifikasi dari semua outlet milik user tsb. Masih dibatasi `user_id` jadi bukan cross-tenant penuh, tapi melanggar pola wajib "setiap query harus scope outlet_id" yang disebut di `CLAUDE.md`.
- **Rekomendasi singkat**: Wajibkan `outletId` (400 kalau kosong) alih-alih silently drop filter, sejalan dengan pola validasi merchant di `AuditLogsService.getAuditLogs`.
